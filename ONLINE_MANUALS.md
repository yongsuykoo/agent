# Durable online PDF study

Version 0.22.0 adds public PDFs to the catalog-backed initial and deeper research pipeline. Existing public HTTPS, destination, redirect, TLS and byte-limit checks apply. Network worker threads collect at most five PDF bodies per research batch; the catalog owner persists them in SQLite only for the same present app generation. PDF discovery defers parsing and never claims an operational capability. HTML/text sources can establish a blueprint while discovered PDFs remain pending.

The background campaign uses the installed-manual reading path for both local files and public snapshots. It processes at most 32 pages/24,000 retained characters per section through the existing isolated parser. Public identity includes application generation, requested/final URL, exact raw-byte hash and reader revision. Each read checks the current registered bytes and cache provenance. Validated capabilities, source citations and reading cursor commit atomically. Introductory text stays in a draft until a cited procedure exists. Blank/scanned sections advance with gaps and no model request. Restarts resume without downloading an unchanged snapshot for every section.

One due public source can be refreshed alongside normal reading in each learning cycle; a large reading queue does not prevent refresh. A source becomes due twenty-four hours after a successful acquisition/refresh. An unchanged hash/final URL retains its cursor. Changed bytes or destination start a new snapshot identity; old page evidence is historical and cannot advance the new cursor. Reading reports explicitly say they describe a retained snapshot. Refreshes download the complete bounded PDF; conditional HTTP caching is not implemented. Requests preserve the inherited proxy/TLS configuration and send no provider Authorization header.

Source refresh has its own atomic owner lease. Expired/replaced owners, cancelled downloads and obsolete app generations cannot replace current data. Captures observed earlier cannot overwrite later registered captures. Refresh failures retain useful cached reading and retry after fifteen minutes. Reading may continue from a retained snapshot while the publisher is unavailable; current publisher freshness is not guaranteed. Source metadata and raw PDF bodies stay in the local catalog, not in cloud task reports. Updates/removals prune old-generation raw snapshots; earlier reading evidence remains keyed to its original identity.

Completed manuals without procedures are excluded from repeated initial interpretation, and the normal research queue seeks alternative sources. Initial/deeper study and the resident/background campaign register discovered PDFs on the catalog-owning thread. A provider failure affecting another fetched source does not discard an already acquired PDF. Ad hoc CLI/UI research without this catalog context still reads one bounded batch. A zero study limit remains uncapped; configured model usage limits and credential/quota backoff remain respected. Refresh itself makes no model request, although subsequent section interpretation may incur provider charges.

The pinned parser, BSD license and installation dependencies are unchanged. Bounds remain 5 MB/PDF, 1,024-page tree, eight-second wall, six-second CPU and 256 MiB parser memory. Public snapshots are ordinary untrusted source evidence; procedures, embedded scripts and attachments are never executed by research. These limits are resource controls, not a general OS security sandbox. Storage grows with the number of current sources and retained reading evidence; this release does not implement a total-disk quota or general history compaction.

`windows\TestDocuments.cmd` now runs sixteen checks, including owned HTTP streams for online discovery through front matter/blank pages, restart, unchanged-source cursor retention and changed-source reading. The fixture substitutes public HTTPS transport and model responses; parser, HTTP streams, SQLite and process APIs are real. A separate cloud check retrieved a real public PDF over verified HTTPS without a provider request. Completed hosted Windows and fresh-wheel evidence is recorded in VALIDATION_022.md. OCR, encrypted/oversized PDFs, broad native application use, live voice/model reliability and universal app/OS mastery remain gaps.
