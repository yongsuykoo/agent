# Independent first-manual study

Version 0.21.0 removes the need for an existing operational blueprint before background study can read an installed PDF. The normal campaign selects a discovered manual, reads its next bounded section, validates cited procedures, and commits progress. There is no separate user demonstration or command for each section.

When a section contains only introductory text, its source evidence and explicit gap remain in a durable current-generation draft. Blank or scanned sections retain textless page gaps and advance without a model request. The agent continues to later readable sections after restart. A draft does not count as a documented app and cannot supply a practice plan. When a cited operation is found, it publishes the first blueprint while retaining earlier source sections and limitations. The operation remains execution-unverified until separately tested.

A manual-reading status excludes the app from parallel initial research while other apps can still be studied. Each manual has an atomic owner lease. Concurrent manuals merge against the latest committed draft or blueprint; one failed reader cannot release another active reader to duplicate initial research. A confirmed exited worker can be replaced using existing process-liveness checks. Cancellation rolls back draft/blueprint and cursor together. App updates/removals and changed manual bytes reject obsolete results; old generation drafts cannot become new generation knowledge.

If all discovered PDF sections end without a usable procedure, the app returns to the normal research queue for other local/public documentation. Exhausted sections are not repeatedly interpreted. Provider or parse failure retains the exact pending section with a fifteen-minute retry delay and permits alternative research when no other manual reader is active. Campaign-wide credential/quota backoff and configured usage limits remain respected; zero daily limit is uncapped. Interrupted provider calls can be billed again after recovery.

Each parser process retains the existing 5 MB input, 1,024-page tree, 32-page/24,000-character section, eight-second wall, six-second CPU and 256 MiB memory limits. Evidence reports expose reading progress and whether an operational blueprint exists. These fields measure reading evidence rather than full software understanding. Catalog-backed public PDF study now continues across batches; see ONLINE_MANUALS.md. Ad hoc research without a catalog retains one bounded batch. OCR, encrypted/oversized manuals, universal source-code knowledge, broad native app operation and actual third-party installation/update adaptation remain gaps.

`windows\TestDocuments.cmd` runs sixteen owned document checks automatically without a provider key or desktop supervision. The new acceptance cases read a seventy-page newly discovered manual through front matter, a blank middle section and later instructions, reopening the catalog before publication. They also verify that an exhausted manual without instructions retains its gaps and queues other research. Parser, filesystem and SQLite effects are real; provider interpretation is simulated. Hosted Windows/Python acceptance is recorded separately in VALIDATION_021.md.
