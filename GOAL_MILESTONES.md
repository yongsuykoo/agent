# Evidence for the personal-agent goal

The goal is independent discovery, study, practice, operation and troubleshooting of current and future Windows apps through chat/voice. It is open-ended: a percentage is not meaningful without a defined acceptance set. The earlier 20–30% estimate was an informal estimate, not a measurement. Adding code or passing simulated tests cannot establish 80% of universal app mastery.

Use the following milestones to plan and evaluate a broad Windows release. A milestone needs live evidence for its stated acceptance target; implemented code alone is insufficient. Passing eight milestones would mean eight of this ten-item release acceptance set, not 80% understanding of every installed app.

| Milestone | Acceptance target | Evidence currently available |
| --- | --- | --- |
| Discovery and changes | Detect installed apps and correctly queue a real new installation/update/removal | 404 apps discovered live; changes/version invalidation simulated |
| Independent study | Find applicable user/technical documentation for five distinct app families with source evidence | Calculator documented live; follow-up study and queue simulated |
| App operation | Three useful independently verified workflows in each of five app families, including an editor, browser, file manager and image tool | Specific Notepad/Calculator workflows passed live; broader support unvalidated |
| Independent practice | Generate and execute new experiments from documentation, retain evidence and continue across restarts | Calculator experiment passed live; new documentation-to-practice check and persistent campaigns not live-tested |
| Troubleshooting | Diagnose and recover from three reproducible app failures without unapproved system changes | Bounded action/verification recovery simulated; broad repairs unfinished |
| Multi-app workflows | Finish and verify a task spanning at least two different app processes | Unfinished; existing runner targets one window |
| New-version adaptation | Relearn/retest affected operations after a real app update, preserving historical evidence | Catalog generations and stale-plan rejection simulated |
| Chat and voice | Route a spoken and typed task to the right app and verify the requested effect | Typed Notepad/Calculator tasks passed; real microphone-to-task acceptance pending |
| Authorization and stop | Verify scope, cancellation and restart behavior on the live Windows host | Signed/encrypted 0.6.5 named-host pairing and permitted native test/inventory jobs verified live; Windows cancellation and restart acceptance pending |
| Usability and performance | Fresh Windows setup, understandable progress/recovery, and measured responsiveness during research/tasks | 0.6.5 companion starts and the cloud retrieves nine passed native checks on Windows Python 3.14.0; broader usability and performance measurements pending |

The 0.4.6 uploaded report remains the earlier live baseline: 12 passed checks, no failures/skips/cancellations. Version 0.5.0 added a thirteenth automatic documentation-to-practice check. On October 8, 2026, the cloud established signed/encrypted pairing with the 0.6.5 companion through the account-owned named hostname and ran the automatic Windows suite: nine native checks passed, none failed or were cancelled, and four AI checks were skipped because AI jobs were disabled. A separate remote inventory job completed with 404 apps. The new documentation-to-practice check and broader research/practice still require live AI-enabled validation. Reports and installed-app metadata remain private in ignored `remote-results`.

After pairing, first verify the host connection and complete automatic self-test. Then inspect inventory/accessible controls, research unfamiliar apps, request permission for disposable windows, and execute bounded workflows with independent expected outputs. Retain failures as gaps. Do not translate documentation counts, inventory totals or simulated test counts into a goal-completion percentage.
