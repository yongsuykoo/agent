# Evidence for the personal-agent goal

Version 0.7.2 adds parallel research, optional uncapped daily usage, guarded local replay/cached plans, and Windows registry notifications. All 237 cloud checks pass; the repeated two-app simulation uses zero model calls after five initially. Native notifications, real installation adaptation and Windows latency remain unverified. See PERFORMANCE.md; this release does not complete the universal goal.

The goal is independent discovery, study, practice, operation and troubleshooting of current and future Windows apps through chat/voice. It is open-ended: a percentage is not meaningful without a defined acceptance set. The earlier 20–30% estimate was an informal estimate, not a measurement. Adding code or passing simulated tests cannot establish 80% of universal app mastery.

Use the following milestones to plan and evaluate a broad Windows release. A milestone needs live evidence for its stated acceptance target; implemented code alone is insufficient. Passing eight milestones would mean eight of this ten-item release acceptance set, not 80% understanding of every installed app.

The 0.4.6 uploaded report remains an earlier baseline: 12 passed checks, no failures/skips/cancellations. Version 0.5.0 added a thirteenth documentation-to-practice check. On October 8, 2026, the cloud authenticated the 0.6.5 companion and ran the AI-enabled suite: **11 passed, two failed, none skipped or cancelled**. All native checks and both AI Notepad replacements passed. AI Calculator produced the wrong answer, and independent Notepad study generated an inconsistent experiment that was rejected before execution. A bounded five-app study documented three apps and deferred two; the persistent catalog has eight documented apps and 35 unverified capabilities among 404 discovered apps, with no observed capability tests or ready experiments. The subsequent live 0.6.6 suite passed **12 checks and failed one**, with none skipped or cancelled. AI Calculator now passed after seven actions, with display 45; independent practice was still rejected because the planner reported no suitable disposable experiment despite researching five Notepad capabilities. The subsequent bounded study batch left the persistent catalog at ten documented apps, 45 unverified capabilities and three ready plans, with no observed capability tests. Version 0.6.7 supplies observed editor controls, allows one scope-focused follow-up documentation study on unsupported practice, and preserves diagnostic evidence; 184 cloud regression tests pass, and the subsequent live 0.6.7 retest passed all 13 checks with no failures/skips/cancellations. It independently expanded Notepad study to ten capabilities, generated a new exact-text experiment and verified one capability after execution. A read-only persistent catalog check confirmed ten apps / 45 capabilities / three pending plans survived the helper restart. This does not establish all-app mastery or repeated reliability. Reports and installed-app metadata remain private in ignored `remote-results`.

After pairing, first verify the host connection and complete automatic self-test. Then inspect inventory/accessible controls, research unfamiliar apps, request permission for disposable windows, and execute bounded workflows with independent expected outputs. Retain failures as gaps. Do not translate documentation counts, inventory totals or simulated test counts into a goal-completion percentage.
